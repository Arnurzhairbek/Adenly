# Threat Dragon: Adenly моделін ашу және экспорттау

## Дайын файл

[threat-dragon.json](threat-dragon.json) — Threat Dragon v2 форматына дайындалған импорт файлы. Ішінде бір сыртқы пайдаланушы, бір Adenly API үдерісі, бір PostgreSQL қоймасы, үш сенім аймағы, төрт бағытталған ағын және алты STRIDE қаупі бар. Барлық қауіп Open күйінде: жоспарланған шара орындалды деп көрсетілмейді.

Файл ресми Threat Dragon v2 JSON схемасымен тексерілді; элементтер мен порттарға сілтемелер және алты санаттың болуы да тексерілді. Браузерде графтың ашылуы мен редактордан қайта сақталуы әлі орындалмаған. «Импортқа дайын» және «Threat Dragon-да тексерілген экспорт» — екі бөлек нәтиже.

## Браузерде орындау

1. GitHub-та `docs/security/threat-dragon.json` файлын ашып, **Download raw file** арқылы жүктеп ал. Файл атауы `.json` болып қалсын; GitHub HTML бетін сақтама.
2. https://www.threatdragon.com/ сайтын аш. Жергілікті файлмен жұмыс режимін таңда: **Local Session** немесе **Start a local session**. Бұл режим үшін GitHub аккаунтына кіру міндетті емес. Нұсқаға қарай батырма атауы аздап өзгеруі мүмкін.
3. **Open an existing threat model** / **Import** бөлімін аш. JSON файлын импорт өрісіне сүйреп апар немесе **Open** арқылы таңда. Балама: файлдағы JSON мәтінін толық қойып, **Import** бас.
4. `Adenly — ЛЗ 7 STRIDE` моделін ашып, **Тестілеу API — деректер және сенім шекаралары** диаграммасын таңда. Қажет болса **Edit** арқылы редакторға кір; сызба көрінбесе zoom/fit арқылы толық көрсет.
5. Мыналарды тексер: TB1 ішінде пайдаланушы, TB2 ішінде API, TB3 ішінде PostgreSQL; F1–F4 көрсеткілері бар; F1, F2 және API элементтерін таңдап, алты қауіп пен mitigation өрістерін аш. Төмендегі тізіммен салыстыр. Әр қауіптің иесі сипаттамасында жазылған. Аяқталмаған шараны **Mitigated** деп өзгертпе.
6. Диаграммада өзгеріс болса **Save**, содан кейін модель редакторында да **Save** басып, JSON файлын сақта/жүкте. Кей нұсқада модель бетінен **Edit → Save** қажет. Жергілікті сақтау диалогында атауын `threat-dragon.json` қой. **Export → TM-BOM** — басқа формат; осы тапсырмадағы негізгі дәлел ретінде native Threat Dragon JSON сақта.
7. Сақталған файлды қайтадан **Open/Import** арқылы аш. Үш аймақ, үш негізгі элемент, төрт ағын және алты қауіп сақталғанын тексер. Осы қайта ашу қадамы экспорттың жарамдылығын көрсетеді.
8. Сақталған native JSON-ды GitHub-тағы `docs/security/threat-dragon.json` орнына жүкте. `threat-model.md` және ЛЗ 7 README-да тексеру күнін және шын орындалған әрекеттерді жаз. Қосымша: диаграмма скриншоты және **Report → Print / PDF** есебі; бұлар JSON-ды алмастырмайды.

## Алты қауіп қай жерде?

| Санат | Файлдағы қауіп | Қай элементте | Шараның мазмұны |
|---|---|---|---|
| Spoofing | T-S | F1 | JWT ұрлануын азайту, XSS қорғанысы, токенді қайтарып алу |
| Tampering | T-T | F1 | Сұрақ/жауаптың осы тестке қатысын тексеру, транзакция |
| Repudiation | T-R | Adenly Test API | Actor/request_id/action/object/outcome/time аудиті |
| Information disclosure | T-I | F2 | Иелікті тексеру, ішкі қате мәліметін шығармау |
| Denial of service | T-D | Adenly Test API | Responses көлемі, timeout, submit шектеулері |
| Elevation of privilege | T-E | Adenly Test API | Рөлді БД-дан тексеру немесе token revocation |

Модель HTTPS және БД шифрлауын орнатылған факт деп көрсетпейді. Production-дағы қорғаныс бөлек тексеріледі. Қауіптердің severity бағалары — команданың бекітуін күтетін бастапқы сараптамалық бағалар.
