Бұл жауап live Projects тақтасын оқу/өзгертуге мүмкіндік бермеді. Тақта бар/жоқ деген қорытынды шықпайды; жаңа тақта, view немесе өріс жасалды деп саналмайды. Токен мәндері оқылмады және құжатқа салынбады.

## Бір рет орнату

GitHub Projects-ке қолжетімді өз құрылғыңызда GitHub CLI арқылы кіріп, қажетті project рұқсатын беріңіз. Жеке токенді чатқа жібермеңіз. Алдымен қолданыстағы тақталарды тексеріңіз; бар тақтаны қайта жасамаңыз.

```bash
gh project list --owner Arnurzhairbek
# Қолданыстағы тақта болса:
python docs/lz9/scripts/setup_board.py --project NUMBER
# Тақта жоқ екені анықталса ғана:
python docs/lz9/scripts/setup_board.py --create
```

Скрипт әдепкіде тек жоспарды көрсетеді; жоғарыдағы explicit flag қана live өзгеріс жасайды. Ол Status опцияларын оқып, саясаттан айырмасын көрсетеді; қолданыстағы статус/карточка мәндерін сақтап, оларды API арқылы ауыстырмайды; Sprint, StartedAt, DoneAt, BlockedReason, Source өрістерін қосады, readme саясатын сақтайды және жобаны Adenly-мен байланыстырады. Қайта іске қосқанда бар өрістерді қайталамайды. Скрипт осы ортада тек жоспар/синтаксис деңгейінде тексерілді; live мутация орындалған жоқ.

GitHub UI ішінде **Board** көрінісін ашып, **Group by: Status** таңдаңыз; Sprint бойынша сүзгі қолданыңыз; In Progress лимиті 2/адам, Review 3/команда екенін view атауы/сипаттамасына енгізіңіз. Status-қа Backlog, Ready, In Progress, Review, Done опцияларын және кестедегі column descriptions-ты UI арқылы енгізіңіз; бар карточканың күйін жоғалтпай сәйкестендіріңіз. View мен status опцияларын API арқылы өзгерту бұл скриптке кірмейді. WIP native hard limit емес, күнделікті саяси/скрипттік бақылау. Осы UI қадамдары аяқталмайынша «live доска толық бапталды» деп жазбаңыз.

Қолданыстағы issue-ларды қосу керек болса, карточка DoR-ға сай болғанда қосыңыз. SIM-01–SIM-14 — тек CSV симуляциясының ID-лері, GitHub issue ID-лері емес. Скрипт нақты #3–#10 issue-ларын жаппайды және симуляцияны шынайы Done тарихына айналдырмайды. Оқу үшін draft-карточка жасалса атауы міндетті түрде `[SIMULATION]` деп басталуы керек.

## Деректерді алу

View мәзірінде CSV Export болса пайдаланыңыз. Болмаса:

```bash
python docs/lz9/scripts/export_current_board.py --project NUMBER --output board_snapshot.csv
```

Бұл скрипт толық current snapshot алады, бірақ **статус ауысуларының тарихын қалпына келтірмейді**. Issue created_at немесе closed_at күнін In Progress / Projects Done күні деп алмастыруға болмайды. StartedAt/DoneAt DATE өрістерінің күні ғана бар болса, сағатты 09:00 деп ойдан қосуға болмайды.

Нақты цикл мен мәртебе уақыттары үшін [бос event журналын](data/real_transition_log_TEMPLATE.csv) толтырыңыз: item_id, sprint, timestamp, event, from_status, to_status, actor, source. Мысалы timestamp үлгісі `2026-11-02T09:00:00+05:00`; source нақты деректің шығуын көрсетеді. Review-ді нақты алған кезде `review_started` оқиғасын жазыңыз; ол Review күйін өзгертпейді. API snapshot пен журналды бірге сақтаңыз; толық емес тарихтан метрика ойдан шығарылмайды.

Нақты журнал үшін терезе/carryover/rework адаптациясы қажет; дайын симуляция есебін «нақты тарих» деп қайта атауға болмайды.
