# ЛЗ 10 — жеткізу метрикалары және командалық ереже

Орта: **staging**, тұрақты синтетикалық тест стенді. Бұл құжат — енгізуге дайын ереже; нақты оператор/сервер әлі берілмеген. Production немесе нақты студенттік дерекке рұқсат бермейді.

## Нені deployment деп санаймыз?

Белгілі толық commit SHA серверге жеткізіліп, Docker Compose арқылы іске қосылып, frontend, `/health` және `/api/courses` тексеруі өткен кезде ғана deployment `success` болып жазылады. Әр release GitHub Deployments API-де жеке ID алады. Бір ID-ге бірнеше success status келсе алғашқысы ғана алынады. CI build, уақытша CI Docker smoke, PR merge және осы onboarding ортадағы жергілікті жаттығу deployment жиілігіне қосылмайды.

Rollback жазбасы `payload.operation=rollback` арқылы ажыратылады және жаңа функционалдық release жиілігіне кірмейді. Тек сәтті staging release-тер есептеледі; сәтсіз build/басталмаған rollout бөлек CI дерегі ретінде қалады. Staging жабылса немесе deployment журналынсыз қолмен өзгерсе, өлшеу толық емес деп белгіленеді.

## Төрт өлшем

| Метрика | Осы жобадағы есептеу | Дерек көзі |
|---|---|---|
| Deployment frequency | Терезедегі сәтті release deployment саны / (терезе күні / 7) | GitHub Deployments + statuses, environment=staging |
| Lead time for changes | Deployment head commit-інің committer уақытынан сол deployment алғашқы success-іне дейінгі сағаттардың медианасы | GitHub commit API және deployment success; бұл релиздегі әр коммиттің толық таралымы емес |
| Change failure rate | Сәтсіз өзгеріске байланыстырылған unique deployment ID / 24 сағаттық бақылауы толық eligible change саны ×100% | Deployments және расталған инцидент журналы |
| Failed deployment recovery time | Инцидент басталуынан қалпына келтіру расталғанға дейінгі сағаттардың медианасы | Қолмен жүргізілетін инцидент журналы; unresolved саны бөлек |

Терезе: әдепкіде соңғы 28 тәулік, `[start,end)`, барлық уақыт ISO 8601 UTC не нақты offset-пен. Дашборд жиналған уақыт пен нақты шекараны көрсетеді. Нөлдік deployment кезінде жиілік 0, lead/CFR/recovery — N/A. API 403 немесе толық емес pagination кезінде жиіліктің өзі де N/A; бұл нөл емес.

**Сәтсіз өзгеріс:** release-тен кейін 24 сағат ішінде соған байланысты hotfix керек болды немесе сол release-ке байланысты rollback жасалды. Түзету/rollback байланысын адам incident ledger-де растайды. Бір өзгеріске екі incident болса CFR numerator-ында бір рет саналады. Соңғы 24 сағаттағы жаңа релиздер толық бақылау жоқ болғандықтан CFR denominator-ына кірмейді.

`incidents.csv` — шынайы инциденттер ғана. `incident_observation.csv` — журналдың қандай терезе үшін толық екенін QA растайтын жол. Журнал бос және мұндай бекіту жоқ болса «ақау болған жоқ» деп болжай алмаймыз. Recovery үшін инцидент жоқ болса N/A; API run duration немесе CI түзету уақыты MTTR орнына қолданылмайды. Restore жаттығулары инцидент метрикасына қосылмайды.

CFR eligible change-ке сәтті release және success status-ына жетпей қызметке әсер етіп, incident журналымен расталған failed rollout кіреді. Соңғысы үшін in_progress басталуы алынады; оқиға/уақыт адаммен расталады. Сәтсіз SSH/build пен қызметке әсері жоқ әрекет CFR-ге қосылмайды. Failed rollout DF/lead-ке сәтті release ретінде кірмейді.

## Бағалау шкаласы

Бұл — команда талқылауына арналған **жергілікті оқу шектері**, қазіргі DORA ұйымдарының әмбебап рейтингі немесе ресми Elite/High санаты емес. Метрика мәндері өз репозиторийінен алынады; төмендегі шектер есептелген нәтижелердің орнына қолданылмайды.

| Метрика | Жоғары | Орта | Төмен |
|---|---|---|---|
| Deployment/week | ≥5 | ≥1 және <5 | <1 |
| Median lead time | ≤24 сағ | >24–168 сағ | >168 сағ |
| CFR | ≤15% | >15–30% | >30% |
| Median recovery | ≤1 сағ | >1–24 сағ | >24 сағ |

Дерек жоқ кезде деңгей «Бағаланбайды». Жаңа staging ортасында 0 release шығуы команда жалпы нашар жұмыс істейді деген қорытынды емес; өлшеу арнасы енді іске қосылып жатыр. Үлгі саны әр метрикамен бірге беріледі.

## Үш күндік тармақ ережесі

Feature branch өмірі ең көбі **72 сағат**: шағын PR → жасыл CI → басқа адамның бір review-і → merge. Үлкен жұмыс feature flag/шағын тәуелсіз PR-ларға бөлінеді. Шек асса PM себебін және қайта бөлу шешімін тіркейді. Бұл native GitHub branch setting емес, команда келісімі. Күн сайын ашық PR/тармақ жасы қаралады; red CI өшіріліп немесе `main`-ға тікелей push арқылы айналып өтілмейді.

Басқа адамның review-і — нақты адам бекітетін қадам; осы агент өз PR-ын мақұлданды деп көрсетпейді.
