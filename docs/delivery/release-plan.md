# Релиз жоспары, шығару және откат чек-листтері

Барлық уақыт **Asia/Qyzylorda**. Тұрақты сервер берілмейінше төмендегі терезелер — ұсыныс; орындалған релиз есебі емес.

## Терезе және жауаптылар

Ұсынылған алғашқы тұрақты staging терезесі: **10.11.2026, сейсенбі, 15:00–16:00**; келесі — **12.11.2026, бейсенбі, 15:00–16:00**. Сервер дайын болмаса release орындалмайды, PM күнді қайта келіседі. Жұма/демалыс қарсаңы таңдалмайды. Нақты пайдаланушы жүктемесінің шыңы өлшенбеген, сондықтан осы уақытты оператор мен тапсырыс беруші алдын ала тексереді; шыңға түссе терезе ауыстырылады.

|---|---|---|

PM тапсырыс берушіге жоспарланған релизден кемінде бір жұмыс күні бұрын scope/терезе/күтілетін әсерді хабарлайды. Басталғанда, аяқталғанда немесе rollback кезінде нақты күй мен келесі жаңарту уақытын береді. Осы тапсырма аясында сыртқа хабарлама жіберілген жоқ.

## Релиз чек-листі

- [ ] Сервер, оператор, backup орны және synthetic-only шекарасы расталған; `STAGING_HOST/USER/SSH_KEY/KNOWN_HOSTS` қауіпсіз settings ішінде бар.
- [ ] Бір толық SHA таңдалды; дәл сол SHA-ға `CI required` жасыл; 50% line coverage, secret scan, backend/frontend/Docker және DORA calculation tests өтеді.
- [ ] Басқа адамның бір review-і бар; `main` protection-ның шынымен қолданылғаны және red CI merge-ті бөгейтіні дәлелденген. Қазір бұл тармақ GitHub plan/құқықпен blocked.
- [ ] SEC-01/басқа ашық P1/P2 қаупі бағаланған; осы зертханалық deploy production/нақты студентке рұқсат ретінде қолданылмайды.
- [ ] Алдыңғы known-good SHA, екі image және оның release bundle-і сақталған; `current/previous` көрсеткіштері тексерілген.
- [ ] DB-ға кері үйлеспейтін migration жоқ. Бұл workflow schema migration жасамайды; қосу үшін бөлек forward/backward жоспары керек.
- [ ] Backup алынады, restore нұсқаулығы/қолжетімділігі белгілі; rollback DB volume-ды жоймайды.
- [ ] PM go/no-go тіркеді және байланыс жасалды.
- [ ] `Staging delivery` дәл SHA-ны орналастырып, `/health`, `/api/courses`, frontend smoke өтті; deployment success тек содан кейін жазылды.
- [ ] QA fresh-session негізгі сценарийін тексерді; deployment ID, SHA, уақыт, CI/run URL және белгілі шектеулер сақталды.
- [ ] Келесі 24 сағат бақылау және қажет болса incident ledger толықтығын растау тағайындалды.

## Откат чек-листі

1. **Шешімді Есеркенов Абдулазиз жеке қабылдайды: блокер расталғаннан кейін 5 минут ішінде, қосымша келісімді күтпей.** Ол қолжетімсіз болса релизді бастауға болмайды; ауыстыратын бір тұлға алдын ала жазбаша тағайындалады. Бұл — команда бекітетін ұсынылған тәртіп.
2. QA инцидент уақытын, failed deployment ID және әсерін тіркейді. PM release-терді тоқтатып, тапсырыс берушіге күйді хабарлайды.
3. Алдыңғы known-good SHA және оның retained backend/frontend images барын тексеру. `main~1` деп болжауға болмайды.
4. GitHub Actions → **Staging delivery → Run workflow**, operation=`rollback`, target_sha=`толық known-good SHA`. Target бұрын сәтті сақталған bundle болуы тиіс.
5. Script ескі images-ті қайта құрмай қолданады; сол PostgreSQL volume сақталады. **`docker compose down -v`, БД reset немесе болжамды schema rollback қолданылмайды.**
6. Егер schema кері үйлеспейтін болса, алдын ала келісілген restore/forward-fix рәсіміне өту; дерек жоғалту қаупін PM/операторға дереу хабарлау. Автоматты SQL restore жоқ.
7. `/health`, `/api/courses`, frontend және негізгі пайдаланушы сценарийін тексеру; тек содан кейін қалпына келді деп белгілеу.
8. Incident ledger-ге нақты restored_at, remediation=rollback, адам-сағат және evidence URL енгізу. Deployment outcome separately recorded; rollback жиілікке жаңа feature release ретінде кірмейді.
9. Жаңа release-ті себеп/регрессия/QA review аяқталмайынша ашпау. Жаттығу болса оны DORA incident журналынан бөлек сақтау.

Откаттың оқу жаттығуына ұсынылған техникалық мақсат — **20 минутқа дейін**; нақты қызмет үшін RTO SLA-сы бекітілмеген. Ескі ЛЗ 8-дегі ≤8 сағат мақсат пен осы drill мақсаты әртүрлі шекараға жатады. Дәлелсіз «20 минутта міндетті қалпына келеді» деп уәде берілмейді.
